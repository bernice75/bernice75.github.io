주요 프로젝트

주문 관리 시스템(OMS) 비동기 아키텍처 고도화

2023.08 ~ 현재

Java, Spring Boot 3.x, Spring Event, JPA, QueryDSL, MySQL

문제 상황: 현업 담당자로부터 특정 시점부터 택배사 API 응답 지연으로 관리자 페이지가 최장 7초간 멈추는 현상이 반복된다는 CS를 전달받음. 방치 시 지연이 누적되어 배송 접수 업무 자체가 밀리는 구조적 문제로 번질 수 있어 신속한 대응이 필요했음

왜 이 방식인가: 연동 대상이 단일 택배사였고 실패 시 수기 재접수로 정합성을 회복할 수 있는 구조였기 때문에 메시지 큐 수준의 내구성은 과도한 설계라고 판단. 대신 트랜잭션 커밋 이후 비동기로 실행되는 Spring Event 기반 리스너 분리를 선택해 복잡도를 낮추면서 지연 문제를 해결

  • 트랜잭션 커밋 후 `@Async` 기반 외부 API 호출 리스너가 실행되도록 분리하여 대기 시간을 150~200ms 수준으로 단축
  • UUID 기반 eventId를 발행하여 요청/응답 전문 로깅 및 실패 건 추적성 확보
  • 실패 건 수기 재접수 상태 관리를 통해 외부 시스템과의 정합성 오류 최소화
  • 적용 이후 동일 유형의 지연 CS 재발 없이 안정적으로 운영 중

WebFlux + Netty 기반 동기화 서버 리소스 고갈 장애 분석

2024.10 ~ 2026.01

Java, Spring Boot 3.x, Netty, WebFlux, R2DBC, MariaDB

문제 상황: 매출 확인 사이트 로그인 불가 및 매출 미동기화 CS가 빗발쳐 확인한 결과 DB 커넥션 풀 고갈 로그를 확인. 방치 시 약 3일 주기로 재발하며, 재발할 때마다 매출 사이트 접속 불가로 이어지는 연관 시스템 동반 장애였음

원인 추적 과정: 처음에는 1GB 이상 대용량 데이터 수신 시 처리 실패 문제로 파악되어 버퍼 용량 확대와 JsonObjectDecoder 교체로 해결했으나, 이후에도 커넥션 고갈이 재발. 5초 주기로 커넥션 점유 개수를 로깅해 추적한 결과 중첩 subscribe 구조에서 체인이 중단되면 커넥션이 반환되지 않고 점유 상태로 남는 것을 확인해 근본 원인으로 특정

  • JsonObjectDecoder 기반 객체 경계 프레이밍으로 교체하여 대용량 JSON 예외 문제 해결
  • 중첩 subscribe 구조를 flatMap 기반 단일 체인으로 평탄화하여 예외 발생 시에도 커넥션이 정상 반환되도록 개선
  • 인프라 장애와 앱 결함을 분리 모니터링하여 2026.01 이후 동일 원인 애플리케이션 장애 0건 유지

DeployX: SSH 기반 배포 운영 통제 플랫폼

2026.03 ~ 2026.06

Node.js, React, SSH/SFTP, WebSocket, MySQL/PostgreSQL, Apache, systemd

문제 상황: 수동 SSH 배포 절차에서는 신규 배포 후 문제가 생기면 롤백까지 수동으로 대응해야 해 장애 대응이 지연됐고, Apache Reverse Proxy 적용 이후에는 배포할 때마다 30~60초간 503 응답이 발생하는 무중단 배포 이슈가 있었음

설계 배경: 기존 구조를 크게 바꾸지 않으면서 무중단 전환이 가능한 Blue-Green 배포를 우선 도입. 이후 플랫폼이 실제 운영 환경에 투입될 만큼 고도화되면서, 아무나 배포를 실행할 수 없도록 RBAC으로 권한을 분리하고 누가 언제 무엇을 배포했는지 추적할 수 있는 감사 로그를 추가함. 수동 배포 시절 오류 발생 시점을 특정할 수 없어 매번 원인 분석을 처음부터 반복했던 경험을 바탕으로 배포 이력화를 설계에 반영했고, CI 연동 토큰이 유출될 경우를 대비해 즉시 폐기할 수 있는 구조도 함께 설계

  • Apache Reverse Proxy 환경에서 프록시 심링크 전환 기반 Blue-Green 배포를 적용해 30~60초간 발생하던 503 응답 없이 무중단 전환 및 롤백 흐름 정의
  • 수동 배포 시절 반복됐던 원인 추적 부담을 해소하기 위해 배포 흐름을 이력화·구조화하여 실패 단계와 원인을 UI와 로그에 일관되게 기록
  • RBAC 기반 권한 분리와 배포 이력 감사 로그로 운영 환경 수준의 통제 체계 설계
  • CI 연동 토큰 유출 시 즉시 폐기 가능한 구조를 포함해 동시성 충돌, 로그 누락 등 운영 리스크를 사전 검토하고 구현 결과의 동작 기준 검증 주도
